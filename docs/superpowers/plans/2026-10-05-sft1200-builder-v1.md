# SFT1200 自编译固件第一版(最小运行版)实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建一个 GitHub 仓库(sft1200-builder),用 Actions 从矽昌官方 SDK + GL 官方板级文件编译出 GL-SFT1200 最小运行版固件(官方 WiFi 驱动 + LuCI + 无线 AP + DHCP + argon 主题)。

**Architecture:** 三层拼装——workflow 运行时 clone 矽昌 `Siflower/1806_SDK`(release2.0.0)作源码层,`board/` 目录里的 GL 官方 SFT1200 五件套 overlay 到源码树作板级层,自写 GitHub Actions workflow 作流水线层。本地 Windows 只负责创建文件与提交,所有编译发生在 GitHub Actions(ubuntu-22.04 runner),每个趟坑迭代 = push → 触发 → 读日志 → 打补丁。

**Tech Stack:** OpenWrt 18.06 / Linux 4.14.90(SDK 内置)、GitHub Actions、bash 脚本、git。

**Spec:** `docs/superpowers/specs/2026-10-05-sft1200-actions-firmware-design.md`(与计划同仓,执行前必读)。

## Global Constraints

- 方案甲:除 argon 主题(用户指定,开源第三方)外,所有源码/板级文件只来自 `Siflower`、`gl-inet-builder`、`openwrt` 三个官方/原厂组织;**禁止**引入 wekingchen 仓库的任何文件。
- SDK 固定 `release2.0.0` 分支,并在每次构建记录其 commit hash。
- feeds 必须显式钉住官方 `openwrt-18.06` 分支(禁止用滚动 HEAD,否则 18.06 与 2026 年的 feed HEAD 必然不兼容)。
- 不使用 SDK 的 `make.sh`(其 case 列表不含 gl_sft1200,且含 git tag 版本注入;配置生成改用本计划 `scripts/gen-config.sh`)。
- 不升内核(4.14.90 锁死,用户已确认);第一版不装代理类/VPN 类插件(spec §8.2 第一版范围;argon 与 LuCI 是仅有的两个外部引入)。
- 产物双格式:`*factory*` + `*sysupgrade*`,文件名须含 gl-sft1200 / SF19A28-GL-SFT1200 之一。
- 本地验证仅限:bash 语法(`bash -n`)、目录结构核对、yaml 解析;编译正确性以 Actions 运行为准。
- 每个 Task 结束必须 `git commit`。

### Task 3: apply-board.sh(overlay 脚本)

**Files:**
- Create: `scripts/apply-board.sh`

**Interfaces:**
- Consumes: `board/`(Task 2)。
- Produces: 以 `<sdk-root>` 为参数,把五件套 overlay 进 SDK 树;workflow(Task 6)调用 `./scripts/apply-board.sh sdk`。

- [ ] **Step 1: 写 scripts/apply-board.sh**

```bash
#!/usr/bin/env bash
# 把 board/ 五件套 overlay 进 Siflower SDK 源码树。用法: apply-board.sh <sdk-root>
set -euo pipefail
SDK="$(cd "$1" && pwd)"
OW="$SDK/openwrt-18.06"
TGT="$OW/target/linux/siflower"
KDT="$SDK/linux-4.14.90-dev/linux-4.14.90/arch/mips/boot/dts/siflower"
B="$(cd "$(dirname "$0")/.." && pwd)/board"

for d in "$OW" "$TGT/sf19a28-fullmask" "$KDT"; do
  [ -d "$d" ] || { echo "FATAL: SDK path missing: $d"; exit 1; }
done

cp "$B/sf19a28_gl_sft1200_fullmask_def.config"   "$TGT/"
cp "$B/config-4.14_gl_sft1200"                   "$TGT/sf19a28-fullmask/"
mkdir -p "$TGT/sf19a28-fullmask/profiles"
cp "$B/profiles/sf19a28-gl-sft1200.mk"           "$TGT/sf19a28-fullmask/profiles/"
cp -a "$B/base-files-SF19A28-GL-SFT1200"         "$TGT/sf19a28-fullmask/"
cp "$B/dts/sf19a28_fullmask_gl_sft1200.dts"      "$KDT/"

# 内核 DTS Makefile 是逐板列表:追加 GL_SFT1200 行(幂等)
LINE='dtb-$(CONFIG_DT_SF19A28_FULLMASK_GL_SFT1200)\t+= sf19a28_fullmask_gl_sft1200.dtb'
if ! grep -q 'GL_SFT1200' "$KDT/Makefile"; then
  sed -i "/ROUTER_1211/a $LINE" "$KDT/Makefile"
fi

echo "== overlay done =="
grep -n 'GL_SFT1200' "$KDT/Makefile"
ls "$TGT/sf19a28-fullmask/" | grep -i gl_sft1200
```

- [ ] **Step 2: 写 scripts/gen-config.sh**

```bash
#!/usr/bin/env bash
# 生成 .config:SFT1200 官方 def.config 为底,叠加 LuCI。用法: gen-config.sh <openwrt-18.06>
set -euo pipefail
OW="$(cd "$1" && pwd)"
[ -f "$OW/target/linux/siflower/sf19a28_gl_sft1200_fullmask_def.config" ] || {
  echo "FATAL: def.config not found - run apply-board.sh first"; exit 1; }

cp "$OW/target/linux/siflower/sf19a28_gl_sft1200_fullmask_def.config" "$OW/.config"
cat >> "$OW/.config" <<'EOF'
CONFIG_PACKAGE_luci=y
CONFIG_PACKAGE_luci-i18n-base-zh-cn=y
CONFIG_PACKAGE_luci-mod-admin-full=y
EOF
make -C "$OW" defconfig
echo "== .config generated =="
grep -E 'CONFIG_PACKAGE_luci=|CONFIG_TARGET_BOARD|CONFIG_TARGET_SUBTARGET' "$OW/.config"
```

说明:`CONFIG_PACKAGE_luci-mod-admin-full=y` 是 18.06 LuCI 的完整管理界面包(含网络/无线页面);中文语言包按需可留可删。

### Task 5: verify-image.sh(产物校验)

**Files:**
- Create: `scripts/verify-image.sh`

**Interfaces:**
- Consumes: SDK 编译产物目录 `bin/targets/siflower/`。
- Produces: 退出码 0 = 产物齐备且命名/尺寸合规;workflow 以此为发布门禁。

- [ ] **Step 1: 写 scripts/verify-image.sh**

```bash
#!/usr/bin/env bash
# 校验编译产物:factory + sysupgrade 双格式存在、尺寸合理。用法: verify-image.sh <openwrt-18.06>
set -euo pipefail
OW="$(cd "$1" && pwd)"
BIN="$OW/bin/targets/siflower"
[ -d "$BIN" ] || { echo "FAIL: $BIN missing"; exit 1; }

echo "== all images =="
find "$BIN" -type f \( -name '*.img' -o -name '*.tar' -o -name '*.bin' \) -printf '%10s  %P\n' | sort -k2

factory="$(find "$BIN" -type f -name '*factory*' | head -1)"
sysup="$(find "$BIN" -type f \( -name '*sysupgrade*' \) | head -1)"
[ -n "$factory" ] || { echo "FAIL: no factory image"; exit 1; }
[ -n "$sysup" ]   || { echo "FAIL: no sysupgrade image"; exit 1; }

fsz="$(stat -c%s "$factory")"
[ "$fsz" -gt 8388608 ] && [ "$fsz" -lt 134217728 ] || { echo "FAIL: factory size $fsz out of range"; exit 1; }

# 命名须可识别机型(SF19A28-GL-SFT1200 profile 的 IMG_PREFIX 规则)
ls "$BIN"/*/* 2>/dev/null | grep -qiE 'gl.?sft1200|SF19A28' || {
  echo "FAIL: image name does not reference SFT1200 model"; exit 1; }

echo "OK: factory=$factory ($fsz bytes)"
echo "OK: sysupgrade=$sysup"
```

### Task 6: build.yml(主构建 workflow v1)

**Files:**
- Create: `.github/workflows/build.yml`

**Interfaces:**
- Consumes: Task 2/3/4/5 的全部脚本与文件。
- Produces: Actions 运行产物(Artifact:sft1200-images)。

- [ ] **Step 1: 写 .github/workflows/build.yml**

```yaml
name: SFT1200 firmware build

on:
  workflow_dispatch:

env:
  TZ: Asia/Shanghai
  SDK_REPO: https://github.com/Siflower/1806_SDK.git
  SDK_BRANCH: release2.0.0

jobs:
  build:
    runs-on: ubuntu-22.04
    timeout-minutes: 360
    steps:
      - uses: actions/checkout@v4

      - name: Install host dependencies
        run: |
          sudo apt-get update
          sudo apt-get install -y \
            build-essential gawk git libncurses-dev zlib1g-dev libssl-dev \
            flex quilt xsltproc libxml-parser-perl merge unzip wget file \
            python3 python3-distutils device-tree-compiler swig

      - name: Clone Siflower SDK
        run: |
          git clone --depth 1 -b "$SDK_BRANCH" "$SDK_REPO" sdk
          echo "SDK_COMMIT=$(git -C sdk rev-parse HEAD)" | tee -a "$GITHUB_ENV"

      - name: Apply SFT1200 board files
        run: ./scripts/apply-board.sh sdk

      - name: Setup feeds (pinned openwrt-18.06)
        working-directory: sdk/openwrt-18.06
        run: |
          cp "$GITHUB_WORKSPACE/feeds.conf" feeds.conf
          ./scripts/feeds update -a
          ./scripts/feeds install -a

      - name: Generate .config
        run: ./scripts/gen-config.sh sdk/openwrt-18.06

      - name: Download sources
        working-directory: sdk/openwrt-18.06
        run: make download -j8

      - name: Build
        working-directory: sdk/openwrt-18.06
        run: |
          echo "sdk=$SDK_REPO@$SDK_COMMIT" | tee build-info.txt
          make -j"$(nproc)" || make V=s -j1

      - name: Verify images
        run: ./scripts/verify-image.sh sdk/openwrt-18.06

      - name: Upload images (artifact)
        uses: actions/upload-artifact@v4
        with:
          name: sft1200-images
          path: |
            sdk/openwrt-18.06/bin/targets/siflower/**/*.img
            sdk/openwrt-18.06/bin/targets/siflower/**/*.tar
            sdk/openwrt-18.06/build-info.txt
          if-no-files-found: error
```

### Task 8: 编译趟坑迭代(host 工具链兼容补丁)

**Files:**
- Create(迭代生成): `patches/host/0001-*.patch`、`0002-*.patch` …
- Modify(可能): `.github/workflows/build.yml`(apply 补丁步骤)

**Interfaces:**
- Consumes: Task 7 的失败日志。
- Produces: 全绿构建 + `bin/targets/siflower/` 产物;`patches/host/` 补丁集。

- [ ] **Step 1: workflow 加补丁步骤**(在 Clone SDK 之后、Apply board 之前)

```yaml
      - name: Apply host compatibility patches
        run: |
          if ls patches/host/*.patch >/dev/null 2>&1; then
            for p in patches/host/*.patch; do
              echo "applying $p"
              git -C sdk apply --whitespace=nowarn "$GITHUB_WORKSPACE/$p" || \
              git -C sdk apply --whitespace=nowarn -R --check "$GITHUB_WORKSPACE/$p" 2>/dev/null || true
            done
          fi
```

- [ ] **Step 2: 迭代循环(每轮一个坑一个补丁)**

对每轮失败,按此决策树定位与修复(每类给出标准修法;补丁文件用 `git -C sdk diff > patches/host/NNNN-<slug>.patch` 导出):

| # | 报错特征 | 修法 |
|---|---|---|
| 0 | apt 装包失败 | 从 apt 安装行删掉 22.04 已改名的包(如 `python3-distutils`),或换 `python3-dev`;逐个核对包名 |
| 1 | host gcc 报错 `-Werror` / deprecated 告警升级为错误 | 在对应 `tools/<name>/Makefile` 或源码处 patch:追加 `CFLAGS += -Wno-error=<类别>`,或给 `--disable-werror`;保持"只放宽告警,不改逻辑" |
| 2 | host openssl API 冲突(`SSL_library_init`/`OpenSSL_add_all_algorithms` 等老 API 缺失) | 优先:让该工具用源码树自带 openssl(改其 Makefile 从 `staging_dir/host` 取);次选:patch 老调用为新 API;禁止往系统装 openssl1.0(22.04 无官方包) |
| 3 | `print` 语句/`import cgi` 等 Python2 语法报错 | patch 对应脚本到 py3(四空格、`print()`、`cgi`→`email.parser` 等);改动最小化 |
| 4 | menuconfig/ncurses 链接错误(`tgetent`/`initscr`) | 确认 `libncurses-dev` 已装;若 tools 自编 ncurses 则 patch 其 configure 参数;不要链接系统老 tinfo 路径 |
| 5 | `make download` 阶段 404(源码内 dl/ 列表指向已死 URL) | 从 `downloads.openwrt.org` 对应目录(官方 18.06/19.07 时代 tarball 仍在)或 github 上游 tag 重下,文件放入 `sdk/openwrt-18.06/dl/`,用 workflow 的 `cache/actions` 或直接补一个 `scripts/dl-preload.sh` 按 URL 清单下载放置 |

每轮流程:
1. 读失败日志,按上表定位类别;
2. `git -C sdk diff` 导出补丁入 `patches/host/`;
3. `git commit -m "fix(host): <现象一句话>" && git push`;
4. 重跑 workflow。

- [ ] **Step 3: 收尾固化 .config**

构建首次全绿后,从 run 日志或 artifact 里取 `.config` diffconfig(`./scripts/diffconfig.sh > .config` 在 sdk/openwrt-18.06 下执行得到精简版),放仓库根并提交——此后 workflow 改为直接 `cp "$GITHUB_WORKSPACE/.config" sdk/openwrt-18.06/.config` 跳过 gen-config 的 make defconfig(gen-config.sh 保留作重新生成入口,workflow 加 `if [ -f "$GITHUB_WORKSPACE/.config" ]` 分支)。

- [ ] **Step 4: 验收**

Run(Actions 页):构建全绿,verify-image.sh 步骤输出两行 OK。
Expected: Artifact `sft1200-images` 内含 factory + sysupgrade,文件名含 `gl-sft1200` 或 `SF19A28`。

- [ ] **Step 5: Commit**

```bash
git add patches/ .config .github/workflows/build.yml scripts/
git commit -m "fix(host): full green build on ubuntu-22.04; pin final .config"
```

### Task 9: argon 主题引入

**Files:**
- Modify: `scripts/fetch-board.sh` 或新增 `scripts/fetch-theme.sh`
- Modify: `scripts/gen-config.sh`(追加主题行)

**Interfaces:**
- Consumes: Task 8 的全绿基线。
- Produces: 固件默认 LuCI 使用 argon 主题。

- [ ] **Step 1: 选型确认 18.06 兼容分支**

argon 是用户指定的例外引入项(开源第三方)。候选上游二选一:
- `https://github.com/kongfl888/luci-theme-argon-mod`(社区 mod,曾用于 18.06 场景)
- `https://github.com/jerrykuku/luci-theme-argon`(原版,`lede` 分支面向 19.07+)

操作:
```bash
git clone --depth 1 https://github.com/kongfl888/luci-theme-argon-mod /tmp/argon-a
git clone --depth 1 -b lede https://github.com/jerrykuku/luci-theme-argon /tmp/argon-b
cat /tmp/argon-a/README.md | head -40   # 看其声明的 luci 版本适配范围
```
判定标准:README/Makefile 明示支持 luci 18.06 者胜出;两者都声称或都不声称时,先用 kongfl888 版尝试编译(它是 18.06 生态下已被验证的组合,wekingchen 也用它——只复用公开上游仓库,不触碰其私有文件)。

- [ ] **Step 2: 引入主题源码**

新建 `scripts/fetch-theme.sh`(按 Step 1 选定的仓库/分支,`git clone --depth 1 -b <branch>` 后把包目录拷到 `board/theme/luci-theme-argon/` 供 apply-board.sh 一起 overlay 到 `sdk/openwrt-18.06/package/theme/luci-theme-argon`),在 apply-board.sh 末尾追加:
```bash
if [ -d "$B/theme/luci-theme-argon" ]; then
  mkdir -p "$OW/package/theme"
  cp -a "$B/theme/luci-theme-argon" "$OW/package/theme/"

```

- [ ] **Step 3: gen-config.sh 追加主题行**

(包名与 Step 2 的 Makefile 一致;若主题包名带 -mod 后缀,则同步改。)

- [ ] **Step 4: 重跑构建验证**

push 后触发 workflow。Expected: 全绿;产物 manifest(`.manifest` 文件)中含 `luci-theme-argon`;verify-image 通过。
